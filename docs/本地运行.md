# 本地运行与测试数据库重建

## 1. 后端环境

后端启动时会自动读取 `backend/.env`；该文件已被 `.gitignore` 忽略，保存本机密钥和管理员凭据，不要提交或分享。首次配置时参考 `backend/.env.example` 创建 `backend/.env` 并填写本机值。不要把真实 AppSecret 写入示例文件。

之后每次启动只需在项目根目录运行固定脚本：

```powershell
 .\backend\start.ps1
```

脚本从自身所在目录启动 Flask，因此可从项目根目录调用；按 `Ctrl+C` 停止。只需首次安装依赖：

```powershell
python -m pip install -r backend/requirements.txt
```

本地数据库默认使用 `backend/data.db`。不要为了日常启动运行 `reset_test_db.py --yes`，该命令会清空测试数据库。需要明确重建测试数据时才单独执行：

```powershell
python backend/reset_test_db.py --yes
```

`reset_test_db.py --yes` 会删除数据库中的全部测试数据并根据当前模型重建；不会删除任何源码、文档、参考图片或 Excel 样例。

## 2. 管理员 Web

```powershell
cd frontend
npm install
npm run dev
```

管理员 Web 通过 Vite 的 `/api` 代理访问后端，并自动携带登录令牌。

## 3. uniapp 微信小程序

将 `uniapp/.env.example` 复制为本地环境配置，并把 `VITE_API_BASE_URL` 改为当前环境的 API 地址。真机必须使用微信后台配置的合法 HTTPS 域名，不能使用 `localhost` 或 `127.0.0.1`。

```powershell
cd uniapp
npm install
npm run dev:mp-weixin
```

然后使用微信开发者工具打开生成目录 `uniapp/dist`。项目已配置 AppID `wxdf7bba648b27e7db`；员工登录按钮会取得微信一次性手机号凭证和登录凭证，再由后端交换手机号并匹配已启用员工。不要在客户端或仓库中填写 AppSecret。

域名 `aszxc.top` 审核完成前可在微信开发者工具中使用本地调试；真机调试和生产环境必须把后端部署到微信后台已配置的合法 HTTPS 域名。没有真实 AppSecret 时，自动化测试使用依赖注入的模拟微信交换器，不会接受客户端直接提交手机号。
