# 分单系统 UI 规范

## 使用边界

- `frontend/` 的正式范围只有管理员网页：桌面优先并适配移动浏览器。已有员工网页界面只保留代码，不删除、不继续设计或开发，也不作为正式入口。
- `uniapp/` 的正式范围只有员工微信小程序端。已有管理员页面与相关代码只保留，不删除、不继续设计或开发，也不作为正式入口。
- 管理员功能只在 `frontend/` 维护；其桌面和移动浏览器布局必须覆盖相同的管理员业务功能、权限、状态、校验、计算口径和操作结果。
- 员工端只存在于 `uniapp/`，使用手机竖屏微信小程序流程；不要把员工功能重新加入 `frontend/` 正式范围。
- 本 skill 约束表现与交互，不改变 `需求分析.md` 的业务规则；发现冲突时停下并指出冲突。
- 开始界面工作前读取 `../../../需求分析.md` 的相关章节，再完整读取 [references/ui-spec.md](references/ui-spec.md)。

## 工作流

1. 确认目标为 `frontend` 管理员响应式网页或 `uniapp` 员工端，并定位对应验收场景；列出本页面不应出现的功能。
2. 先画清页面状态：加载、空白、可编辑、校验失败、保存失败、成功、锁定/只读、无权限。
3. 复用当前 Vue/uni-app 结构和本规范的设计令牌，避免引入新的 UI 框架或第二套视觉语言。
4. 先保证最短操作路径、文字可理解、触控尺寸和错误恢复，再处理视觉细节。
5. 管理员功能变更时同时检查 `frontend` 的桌面与移动浏览器布局；允许交互布局不同，但不能因屏幕尺寸缺失功能。
6. 管理网页分别检查常用桌面宽度和手机宽度；`uniapp` 检查窄屏、输入键盘弹出和真机触控。
7. 对照参考规范的检查清单和相关需求验收场景完成验证。

## 不得自行推断

- 不因界面方便而允许管理员代填员工报货量。
- 不把报货量 0 当作未填写，不把失焦作为提交，不提供员工自行解锁或修改入口。
- 不在 Excel 导入界面添加产品资料库匹配；导入简称直接作为批次产品快照。
- 不以颜色、图标或手势作为唯一信息来源，不隐藏关键操作。
- 不为了塞进手机浏览器而缩小整个矩阵；`frontend` 窄屏布局使用卡片、抽屉、分步编辑或可控横向滚动。
- 不继续设计或扩展 `uniapp` 管理员页面；除非遗留代码阻塞员工端构建，否则不顺带修改。

## 输出要求

交付 UI 任务时说明：改动的主流程、覆盖的页面状态、桌面/手机或小程序验证结果，以及未能验证的真机风险。
