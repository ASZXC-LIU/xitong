# 分单系统执行计划

> 本文件是长期开发的里程碑事实来源。详细业务规则见 `需求分析.md`，执行方法见 `开发准备与工作流.md`。

## 总体完成条件

- `需求分析.md` 第 9 节全部 MVP 验收场景通过。
- P0、P1 差距清零；后端测试、管理员 Web 构建、uniapp 微信小程序构建通过。
- 管理员功能在 frontend 响应式 Web 完整交付，员工功能只在 uniapp 正式交付。
- 环境、测试数据库重建、微信配置和运行方式有明确文档。

## M0 安全与可运行基线

- [x] 原项目能力与复用边界盘点，确定最小改造策略。
- [x] 在现有 Flask 应用上完成环境配置和 `.env.example`，不为重构而重构。
- [x] 最终测试数据库模型；安全重建命令已完成，不做历史迁移。
- [x] 管理员账号初始化必须来自显式环境配置，不保留硬编码默认凭据。
- [x] Bearer Token 统一认证、角色装饰器、标准 JSON 错误。
- [x] 员工接口只使用服务端身份，不接受客户端 `user_id` 决定身份。
- [x] frontend 与 uniapp 请求层统一携带令牌并处理 401。
- [x] 后端基础认证/越权自动化测试；两端构建通过。

## M1 基础资料与微信手机号登录

- [x] 员工内部 ID、姓名、唯一手机号、启停状态；不维护员工密码。
- [x] 产品、单位启停与历史快照规则。
- [x] 微信手机号凭证后端交换适配层、员工匹配、会话与模拟测试。
- [x] frontend 管理员基础资料功能完整并适配移动浏览器。
- [x] uniapp 员工授权、拒绝、未匹配与自动登录流程。

## M2 Excel 与手动建批

- [ ] 已审核模板解析和一次性完整错误列表。
- [ ] 原子创建、产品名称快照、全部启用员工范围。
- [ ] 正式批次名称与到货日期确认、导入结果微调。
- [ ] 手动选择资料库产品建批。
- [ ] frontend 管理端完成合法/多错误/大文件导入测试及移动浏览器验证。

## M3 分货与三级汇总

- [ ] 固定精度一位小数、分货大于 0、产品总分货不超到货。
- [ ] 管理员 Web 动态矩阵与移动浏览器适配。
- [ ] frontend 管理端在移动浏览器提供可用的分货编辑方式。
- [ ] 产品、员工、批次总到货/分货/报货/剩余计算。
- [ ] 并发与保存失败保留输入测试。

## M4 员工报货与状态机

- [ ] 本人待办、报货 0、不得超分货、明确提交与幂等。
- [ ] 提交锁定、管理员解锁、员工重报。
- [ ] 自动完成、手动关闭、重开与关键操作审计。
- [ ] 最近 90 天历史和每次 15 天向前加载。
- [ ] frontend 管理员状态操作完整，uniapp 员工真机主流程可用。

## M5 导出与上线准备

- [ ] 页面、打印、Excel 导出数据口径一致。
- [ ] frontend 管理员桌面端/移动浏览器关键流程回归。
- [ ] 响应式、常见手机、错误/空白/锁定状态检查。
- [ ] HTTPS/微信合法域名、备份、日志、健康检查和部署说明。
- [ ] 全部 MVP 验收证据与最终已知问题清单。

## 执行纪律

- 同一时刻只推进当前最前面的未完成里程碑。
- 勾选项目必须同时具备实现和验证证据，证据写入 `开发状态.md`。
- 发现计划遗漏时可补充技术任务，但不得自行改变需求。
