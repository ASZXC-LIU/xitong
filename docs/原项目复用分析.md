# 原项目复用分析与最小改造策略

> 状态：M1 复用结论已落实，2026-10-02  
> 原则：先复用、再局部改造；冻结不需要的代码；只有现有结构无法承载需求时才新增。

## 1. 总体结论

原项目已经具备可运行原型的主要骨架，不应从零重写。应保留 Flask + SQLite、Vue 3 + Vite、uni-app + Vue，以及现有 API 路径、`frontend` 管理员页面结构、矩阵展示、汇总/打印/导出和 `uniapp` 员工移动卡片。主要工作是补安全边界、统一数据口径、修正导入规则和状态机；`uniapp` 已有管理员实现只冻结保留，不再继续对齐或扩展。

阶段 0 采用“在现有结构上增加薄层”的方式：先在 `backend/app.py` 内抽取配置和认证辅助函数、为原路由加权限装饰器、扩充现有模型字段；暂不把后端整体拆成新的包结构。待自动化测试建立后，只有单文件确实阻碍后续功能时再做有测试保护的局部拆分。

阶段 1 继续复用 M0 已增加的内部 ID、唯一手机号、启停字段、token 会话和历史快照字段。基础资料 API 只补可恢复启停与输入校验；微信 HTTP 契约独立为小型 `backend/wechat.py` 适配器，业务路由仍保留在现有 Flask 应用中。管理员资料页沿用 `Admin.vue` 原有区域，员工登录沿用 `uniapp` 原登录页面位置与 request/storage；未重写框架，也未修改冻结的 `uniapp` 管理员页面。

## 2. 后端 `backend/app.py`

### 直接复用

- Flask、Flask-SQLAlchemy、SQLite 和现有启动方式。
- `User`、`CargoType`、`UnitType`、`Batch`、`BatchItem`、`ItemAssignment` 六个核心实体及其关系方向。
- 已有 API 路径：登录、基础资料、批次、批次产品、分货、员工任务、报货、报表和统计。
- `item_dict`、`assignment_dict` 等序列化入口，可扩展字段而不另建重复输出层。
- `werkzeug.security` 密码哈希、现有 token 登录思路和 30 天会话概念。

### 局部改造

- 配置：固定数据库、密钥、CORS 和 debug 改为环境配置，但保留 Flask 应用本身。
- 模型：在现有表上增加启停、到货量、批次状态、锁定状态、时间和审计字段；数量由 Float 改为固定一位小数。测试数据允许清空，所以不写旧库迁移。
- 登录：管理员继续账号密码；员工移除账号密码入口，接入微信手机号凭证。token 改为请求头认证。
- 权限：给现有路由增加登录/角色装饰器，不重新设计一套平行 API。
- 员工接口：保留 `/api/employee/*` 路径，但从服务端登录身份取员工 ID，忽略并最终移除客户端 `user_id`。
- CRUD：删除员工/产品/单位改为停用；批次删除、关闭、重开按新状态规则处理。
- 分货/报货：保留现有 assignment 关系，增加到货上限、一位小数、报 0、锁定/解锁和幂等校验。

### 确需新增

- 环境配置示例、安全测试配置、测试数据库重建命令。
- 微信官方手机号交换适配层及可注入模拟实现。
- 关键管理操作审计记录。
- 自动化测试目录；现项目没有后端测试。

### 不复用的错误逻辑

- 硬编码 `app.secret_key`、默认管理员/员工密码与生产 debug。
- 匿名业务接口和客户端任意 `user_id`。
- 读取批次产品时自动加入全部产品资料库。
- 保存分货时删除重建记录并允许管理员写 `actual_quantity`。
- 把实际报货大于 0 才视为完成的判断。

## 3. 管理员 Web `frontend/`

### 直接复用

- `Admin.vue` 的侧栏、首页、批次列表、基础资料、汇总页面和移动折叠菜单骨架。
- 动态产品×员工矩阵、员工动态列、分货/报货只读展示和横向滚动样式。
- 各级合计函数、打印页面和 `xlsx` 导出能力；公式需要按新后端口径复核。
- `xlsx` 依赖、文件选择和浏览器读取 ArrayBuffer 的能力。
- `Login.vue` 的基础登录表单与加载/错误状态。

### 局部改造

- 把 `Admin.vue` 内的四个 fetch helper 集中补上 Bearer Token、统一错误和 401 退出；先不引入新状态库或 UI 框架。
- Excel 读取入口保留，但解析规则改为审核模板 `A1/B1/A2/B2`，不再识别员工列或匹配产品资料库；校验结果一次全部显示，最终由后端原子创建。
- 矩阵加入公司到货、总分货、总报货、剩余和超量阻止；管理员永远不提交 `actual_quantity`。
- 现有汇总与导出扩展公司到货和剩余，不另写一套计算组件。
- 现有响应式 CSS 作为基础，按 UI skill 修正字号、触控区和手机卡片编辑。

### 冻结保留

- `views/Employee.vue` 及其现有代码不删除、不扩展、不纳入正式入口或验收。
- `HelloWorld.vue`、示例图片等与产品无关的模板资产暂不处理，除非影响构建或正式页面。

### 不复用的错误逻辑

- Excel 把首行当员工表头、根据姓名匹配员工、同时写分货和报货、逐行多次写库。
- 自动把批次命名为日期报货、导入产品强制匹配资料库单位。
- 默认管理员账号密码提示。

## 4. 员工端 `uniapp/`

### 直接复用

- `utils/request.js` 的 H5/微信条件编译请求结构和 `utils/storage.js` 本地存储。
- `pages/employee/employee.vue` 的批次卡片、产品卡片、数量输入、保存中/失败提示骨架。
- `pages.json` 已登记的员工和登录页面结构；管理员页面登记暂不删除。

### 局部改造

- `request.js` 改用环境 API 地址、自动携带 token、统一 JSON 错误与 401；不另建第二套网络库。
- `login.vue` 保留页面骨架，正式流程只提供员工微信手机号授权；已有管理员账号入口代码冻结保留，不作为正式入口。
- 员工页移除 `user_id` 参数和失焦自动提交，改成明确按钮、报 0、锁定和历史分页。
- 开发调试继续复用现有登录页、`storage.js`、`request.js` 与后端 `issue_token`：不在客户端伪造 token；仅由双开关保护的后端开发入口为服务端配置的测试员工签发正常会话。
- 员工任务状态尽量使用后端返回值，小程序只做即时预览，避免重复维护业务规则。

### 冻结保留

- `pages/admin/` 下全部管理员页面、`utils/admin-api.js`、管理员登录跳转和相关打印/导出实现均不删除，但不再扩展、不作为正式入口、不纳入验收。
- 除非这些遗留代码阻塞 `uniapp` 员工端构建或运行，否则不顺带重构；如确实阻塞，只做解除阻塞所需的最小修改。

### 不复用的错误逻辑

- 固定 `http://localhost:5000/api`。
- 短信验证码、员工账号密码、微信 openid 后再短信绑定的复杂登录流程。
- 员工页携带 `user_id`、失焦即提交、把已报 0 判为未报。
- 用前端硬编码用户或伪造 token 绕开后端认证；开发调试必须仍然使用后端签发的员工会话。
- 冻结的管理员代码不得重新成为正式业务入口或形成第二套管理员规则。

## 5. 跨端复用策略

1. 保留现有后端 API 路径作为唯一契约，统一字段为 `user_id`、`allocated_quantity`、`actual_quantity`，后续通过接口测试锁定。
2. 业务状态、数量校验、权限和汇总以后端为权威；`frontend` 管理员端和 `uniapp` 员工端只做各自角色所需的显示与即时预览。
3. 管理员业务只在 `frontend` 维护，并分别验收桌面和移动浏览器布局；`uniapp` 不参与管理员功能对照。
4. Excel 解析和错误校验放到后端形成唯一实现，`frontend` 复用上传、预览和错误展示；`uniapp` 不承担 Excel 导入。
5. 暂不更换 Flask、Vue、uni-app、SQLite、xlsx 或现有路由命名，避免无业务价值的框架迁移。

- 继续使用 `Batch`、`BatchItem.company_quantity` 和 `ItemAssignment` 保存批次产品快照、公司到货量和员工分货；不新增平行数据表。
- 继续使用现有管理员鉴权、`save_assignments()` 的服务端总分货上限校验和 `Admin.vue` 动态矩阵骨架。

### 局部改造

- `list_items()` 改为只读批次自身产品，移除“读取时自动写入全部启用资料库产品”的旧逻辑。
- 手动建批仍复用 `/api/batches`，但只能以资料库中明确选择的产品建立产品快照，并强制提交每项公司到货量。
- 新增后端 Excel 校验/创建接口：复用 Flask 上传和事务，使用 `openpyxl` 严格读取审核格式；前端只保留文件选择、预览和完整错误展示，不再在浏览器匹配员工或分次写库。

### 不复用的错误逻辑

- Excel 旧员工列匹配、把员工列数值同时写入分货和报货、按行创建批次产品。
- 未传公司到货量时以 0 静默代替，或在读取批次时把资料库所有产品写入批次。

## 9. 第一批最小改造顺序

1. 在现有后端中增加环境配置和认证/角色装饰器，保留全部路由路径。
2. 扩展现有 User 与 token 逻辑，先解决匿名访问和伪造员工 ID；补最小 Flask 测试。
3. 复用 Web fetch helper、uniapp request/storage，为现有请求统一加 token 和 401。
4. 验证原有管理员 CRUD/批次/矩阵仍可工作，再进入微信登录和数据模型业务字段调整。
